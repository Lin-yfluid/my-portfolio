# LoRA 微调实战：把大模型训练成「孙悟空」

第一次跑完 LoRA 微调，看到模型用"俺老孙"的口气回话时，确实有点兴奋。但从"能跑"到"能稳定扮演角色"，中间隔着一堆坑。这篇记录整个过程。

## 一、为什么选 LoRA 而不是全量微调

| 方案 | 显存需求 | 训练时间 | 适用场景 |
|---|---|---|---|
| 全量微调 | 极高 | 长 | 数据量大、算力充足 |
| LoRA | 低 | 短 | 风格迁移、角色扮演 |

LoRA 只训练少量低秩矩阵，冻结原模型权重。对个人开发者来说几乎是唯一可行方案——消费级显卡也能跑起来。

## 二、训练前必须先想清楚的三件事

1. **角色定位**：孙悟空是"桀骜、口语化、爱称俺老孙"，还是"取经路上的沉稳行者"？两种人设的数据完全不同。
2. **数据格式**：指令—回复对必须结构一致，否则模型学到的不是人设而是格式。
3. **评价标准**：怎么判断"训练成功"？我用的标准是三个：像不像、记不记得、听不听话。

## 三、数据准备

数据质量比数量重要得多。我最初堆了几百条，效果反而不如后来精挑的几十条高质量对话。原因是低质数据把模型带偏了。

整理原则：

- 每条回复都要**符合人设口吻**，不能有"作为一个 AI 助手"这类句式
- 覆盖多轮对话，让模型学会维持上下文
- 适当加入"拒绝出戏"的样本，比如被问到现代事物时如何用角色口吻回应

## 四、训练中的关键技术点

```text
基础模型 → 加载 LoRA 适配器（rank / alpha 设定）
→ 数据 tokenize → 设定学习率与调度
→ 梯度裁剪 + 混合精度 → 训练循环
→ 定期保存 checkpoint → 观察 loss 曲线
```

几个直接影响效果的参数经验：

- **学习率**：太大容易把模型训"崩"，出现重复输出；太小则学不到人设
- **rank**：角色风格任务不需要很大，过大会过拟合
- **epoch**：不是越多越好，2–3 轮就足够，再多开始退化学到的通用能力

## 五、训练后遇到的问题与排查

### 问题 1：模型开始复读

**现象**：输出固定句式循环，比如连说三遍"俺老孙去也"。

**排查**：学习率偏高、数据里重复样本过多、解码策略过于贪心。降低温度、加入重复惩罚后明显改善。

### 问题 2：多轮之后人设丢失

**现象**：聊到第 4、5 轮，模型开始用普通话书面语回答。

**排查**：上下文截断把 System Prompt 挤掉了。把角色设定固定在上下文中并控制历史长度后解决。

### 问题 3：不遵守指令

**现象**：让它用一句话总结，它给你写三段。

**排查**：训练数据里缺少"格式约束"类样本。补入相应样本后，指令遵循率明显提升。

## 六、和 SFT 的对比

我把同一批数据分别做了 SFT 和 LoRA 训练，直观差异：

- **SFT**：人设更稳，但训练成本高、容易过拟合
- **LoRA**：轻、快、可多版本并存，人设稳定性略弱，需要更精细的数据

## 七、复盘

微调这件事最反直觉的一点是：**调参的时间远少于调数据的时间**。模型表现不好，八成先从数据找原因，而不是怪参数。

另外，一定要有对照测试集。我一开始只凭"感觉像不像"，改了几轮后完全无法判断哪版更好——建立固定的测试问题清单后，改进才变得可衡量。
