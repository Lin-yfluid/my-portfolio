# Vite 项目部署到 Cloudflare Pages：白屏与 Git 推送

第一次把简历网站部署上线时，我以为点个上传就完事了，结果在"页面白屏"上卡了很久。这篇把整个部署过程和新手最容易踩的坑整理出来。

## 一、部署前必须先理解「产物」

这是最核心的认知：**开发时跑的是源码，部署时要传的是构建产物**。

```bash
npm run build      # 生成 dist/ 目录
```

`dist/` 里是压缩、重命名后的 HTML/CSS/JS，而源码目录里是 `.vue`、`main.js` 这些浏览器看不懂的文件。直接把源码传上去，服务器找不到入口文件，结果就是白屏。

| 目录 | 用途 | 能否直接部署 |
|---|---|---|
| 源码根目录 | 开发 | ❌ |
| `dist/` | 构建产物 | ✅ |

## 二、白屏的三个常见原因

### 1. 上传了源码而不是 dist

最常见的。上传前确认目录里有没有 `index.html`，以及 JS 是否是压缩过的。

### 2. 资源路径不对

如果部署到子路径（比如 `example.com/my-site/`），需要在 `vite.config.ts` 里设置 `base`：

```ts
export default defineConfig({
  base: '/my-site/',
  plugins: [vue()],
});
```

否则所有资源会去根路径找，全部 404。

### 3. 终端工作目录错误

现象是 `npm run build` 报找不到 package.json。原因是在错误的目录执行了命令。

**排查**：先 `pwd`（或 Windows 下看提示符路径）确认当前目录，再执行构建。

## 三、Cloudflare Pages 部署流程

1. 登录 Cloudflare → Pages → 创建项目
2. 选择「直接上传」或连接 Git 仓库
3. 上传 `dist` 目录下的**内容**（不是 dist 文件夹本身）
4. 等待部署完成，拿到 `xxx.pages.dev` 链接

**注意**：不同平台对"上传哪一层"的要求不一样，有的要整个 dist，有的要 dist 里的文件。传错一层同样白屏。

## 四、Git 推送失败怎么办

我遇到过 `git push` 反复报网络连接重置，试了几次都不行。当时的处理方式：

1. 先用 `git status` 确认本地提交是否成功（本地成功说明代码没丢）
2. 网络问题无法解决时，改用 GitHub 网页端直接上传文件完成备份
3. 之后配置了稳定的网络环境再重新推送

**经验**：Git 的目的是保留版本，不是必须用命令行。目标达成就行，不要在一个工具上耗死。

## 五、上线后的自检清单

```
□ 首页能正常打开（无白屏）
□ 刷新子页面不 404
□ 图片、字体资源全部加载成功
□ 移动端布局正常
□ 控制台无红色报错
```

## 六、复盘

部署这件事的技术难度不高，难点全在"看不见的地方"：产物在哪、路径怎么配、上传到哪一层。把这三件事想清楚，剩下的就是等待。

现在我做任何前端项目，都会在开发阶段就先跑一次 `build` 并本地预览 `dist`，确保"能不能上线"这件事从一开始就是确定的。
